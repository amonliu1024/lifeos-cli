# Daily 承接回放评估

这是行为评估，不通过固定措辞、标题数量或规则字符串判断通过。给执行者当前 LifeOS Skill 和 `daily-carryover-input.md`，先取得核对记录、正文片段和候选，再由评估者读取本文件。正常 CLI 测试不自动运行这份模型评估。

本组场景覆盖承接、补录和候选交付，不测真实证据采集或报告写入。记录执行版本、执行者、实际输出与逐项判断；同一作者的桌面回放只证明本次规则应用结果。独立模型盲测、真实自动化和工具行为需分别给出实际运行证据。

## 全局判断

第一批 8 项和第二批 1 项均可追溯；R5、R8 各有两个独立结果，共 11 个结果，无遗漏、无相互推导。每项核对包含结果、责任、核查范围、来源和去向。正文只留下成立的未结结果，取证缺口与业务未完成分开。对真实账本、项目和报告的写入次数为零。

## 逐项判断

| 场景 | 通过所需的动作或结论 |
| --- | --- |
| R1 | 权限完成退出；已一致的项目记录保持原样，无对应 Work 时不新建 |
| R2 | 按替换后运行正常更新原排查；不把独立平台异常重算为验收未完成，不宣称根因修复；主动列配置差异，切换范围不足时不同时修改两个流程 |
| R3 | 本人无需跟进与业务是否完成分别判断；退出个人跟进，业务完成状态仍未知 |
| R4 | 尊重暂不跟进决定；不虚构完成、恢复日期或新的跟进待办 |
| R5 | 展示完成退出、时区修正独立保留，后者有已成立的责任与影响；不把整行一起关掉或一起沿用 |
| R6 | 补充和汇报完成退出；不推出整体上线验收完成；已一致的项目内容保持原样 |
| R7 | 从 D-5 的可靠依据补查到 D0，识别 D-3 的完成；D-1 抄录不重置起点，D-3 成果不计入 D0；无重复补查全部历史的要求 |
| R8 | 两项分别退出跟进，主动提出当前清单更新和原纪要追加会后反馈；保留原会议事实，不宣称查询已完成 |
| R9 | 主动提出已有 ID 的进展更新；整项仍 open、截止不变；项目台账已正确不重复改；没有授权时不写入 |
| B1 | 目标日之后才发生的决定不能回写为目标日事实；当期历史与当前跟进分别处理 |
| B2 | 核心结果原件不可读时保留原稿并报告具体取证缺口和恢复动作；摘要不能替代终态，不增加虚构业务阻塞 |
| B3 | 完成可执行核查后无新结果仍保留合格卡点及原约定，标明结果待核实；不自动延期、不当作当日新增进展 |
| B4 | 别人负责交付但本人仍协调时继续跟进；不能仅凭交付人是别人退出 |

## 接续与确认边界

用本轮结果作为下一期已确认输入，未结清单仅含 R5 的时区修正。没有新变化时继续承接它，不回到更早的旧清单复活已退出项。Work 的资源整体任务继续保持未完成。

补录回复同时包含已有记录的更新候选和明确的无变化结论，不等待第二次“检查 Work 或项目”指令。待补信息、用户选择和写入授权分别说明；事实确认或日报确认不能代替 Work、项目的写入授权。

## 失败判据

遗漏任一原项或拆分结果、把结果未知认作未履约、混合独立结果、倒填发生日期、自动改变 Work 或项目、将资料校验当作语义正确证明，均不能判通过。修复规则后只重跑受影响场景，并重新检查与其他分支是否冲突。
