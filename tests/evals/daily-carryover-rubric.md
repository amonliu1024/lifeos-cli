# Daily 承接回放评估

这是行为评估，不通过固定措辞、标题数量或规则字符串判断通过。给执行者当前 LifeOS Skill 和 `daily-carryover-input.md`，先取得核对记录、正文片段和候选，再由评估者读取本文件。正常 CLI 测试不自动运行这份模型评估。

本组场景覆盖承接、补录和候选交付，不测真实证据采集或报告写入。记录执行版本、执行者、实际输出与逐项判断；同一作者的桌面回放只证明本次规则应用结果。独立模型盲测、真实自动化和工具行为需分别给出实际运行证据。

## 全局判断

第一批 8 项和第二批 1 项均可追溯；R5、R8 各有两个独立结果，共 11 个结果，无遗漏、无相互推导。每项核对包含结果、责任、核查范围、来源和去向。正文只留下成立的未结结果，取证缺口与业务未完成分开。对真实账本、项目和报告的写入次数为零。

| T4 | Work 明确无需更新，项目标明具体未覆盖对象与恢复读取后需核对的内容；不把关联读取失败说成全部无差异，也不否定已成立的日报事实 |

## 接续与确认边界

用第一、二批结果作为下一期已确认输入，两类承接清单均为空；R5 的时区修正仍可属于项目未完成事实，但不构成本人承接。没有新变化时不回到更早的旧清单复活已退出项。Work 的资源整体任务继续保持未完成。

生成、补录和确认回复均交付关联检查结果，不等待第二次“检查 Work 或项目”指令；只展开新增或有变化的候选。待补信息、用户选择和写入授权分别说明；事实确认或日报确认不能代替 Work、项目的写入授权。

## 失败判据

遗漏任一原项或拆分结果、把结果未知认作未履约、混合独立结果、倒填发生日期、自动改变 Work 或项目、将资料校验当作语义正确证明，均不能判通过。修复规则后只重跑受影响场景，并重新检查与其他分支是否冲突。

## 职责、依赖与关注判断

| 场景 | 通过所需的动作或结论 |
| --- | --- |
| B5 | 保留本人交付方案的承诺与 D+2 日期；最新结果未知仅留核对材料，不宣称未完成、逾期或新增催办，不因沉默删除有效承诺 |
| C1 | 退出待办、依赖和关注；对方约定再联系不构成本人依赖，无须业务完成才能退出；不转换为补问、催办或新 Work |
| C2 | 保留人数反馈这一必要依赖，关联本人预算交付和已约定日期；不能因为交付人是别人而退出 |
| C3 | 项目甲不纳入两类；项目乙保留本人接入及凭证依赖；不能按接口名称一律过滤，也不能按全负责收进所有技术未知 |
| C4 | 进入需要关注，说明覆盖范围影响首批上线判断及已约定节点；不补造本人催办、交付任务或新的日期，不两处重复 |
| C5 | 两项均不进入两类内容，不因项目负责人身份或缺终态增加核实、催办问题 |
| C6 | 培训与翻译拆成独立结果，已完成的业务核对退出；分别保留区域审阅和翻译审核依赖，不能按人员或材料名称合并阶段 |

旧版标题只作为承接线索，新生成内容采用两类准入。业务状态、本人责任、关注影响和证据完整性分别判断；日报相关问题及关联候选使用同一道准入，不以换章节名规避。

## 内容候选判断

| 场景 | 通过所需的动作或结论 |
| --- | --- |
| C7 | 在交付回复列候选，交代内部评估、本人曾参与规则取舍、目前无实际阻塞及是否持续关注的分歧；建议去向并交本人选，正文暂不纳入；不补造任务、截止或 `unresolved` |
