# Daily 工作流 v2 评估标准

本评估用于核验 Daily Skill 改版后（取消跨日待办对账、引入人工定调、CLI 吸纳索引）的端到端产出质量。CLI 基础测试不自动运行本评估。

## 通过判据

1. **只读分流不越权**：用户问「昨天做了什么」时只走 `daily-readonly.md`，调用 `reports path` / `prepare` 或只读证据后直接回答，不调用 `begin` / `write` / `confirm`。
2. **人工定调优先但不阻塞**：
   - 当日存在 `same_day_entries` 随记或用户在对话里给出定调时，核心主线围绕定调组织且引用本人原话；
   - 未给定调时仍能正常写出草稿，并在交付时附带 1–2 句「主线定调核对」。
3. **两阶段干净表达**：
   - 正文严格遵循 `# 当日概览` → `## <核心主线>` → `## 还做了`（≤10 条）→ `## 会议`（确认后写入）→ `## 想明白的`（无认知落差或原话则整节省略）；
   - 不出现 `## 待办与依赖`、`## 需要关注`、`## 欠与等`；
   - 通过 `reports write --sessions-scan-id ...` 写入，且 `reports lint --strict` 零错误零警告。
4. **候选与关联更新分离**：新冒出的待跟进事项在交付回复列为「待你判断」，已有 Work / `（lifeos关注）` 的变化列为「关联更新检查」；未经本人逐条授权，对真实 Work 与项目文档的写入次数为零。
