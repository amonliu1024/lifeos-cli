# Periodic 工作流

周期报把一段时间内已经确认的日报整理成更长的判断变化。它只消费 Reports Runtime 中的 confirmed 日报，不重新读取 Sessions、Git、DChat 或 Work，也不补采证据。

## 一、确定周期与现状

把用户给出的周、月、季度、半年或自然年归一为 CLI 接受的规范周期：

- ISO 周：`YYYY-Www`，周一到周日；
- 自然月：`YYYY-MM`；
- 自然季度：`YYYY-Q1` 到 `YYYY-Q4`；
- 自然半年：`YYYY-H1` 或 `YYYY-H2`；
- 自然年：`YYYY`。

“本周、上周、本月、上季度、今年”等相对表达以当前 Asia/Shanghai 日期为基准。表达不能唯一确定周期时，只问会改变窗口的一个问题，不自行选择。

```bash
lifeos reports periodic path --period <PERIOD> --json
lifeos reports periodic sources --period <PERIOD> --json
```

先用 `path` 读取既有状态，再用 `sources` 取得 CLI 计算的唯一窗口。`sources` 默认每页返回 7 份 confirmed 日报正文；第一页的 `coverage` 给出完整来源、缺失日期和 draft 日期，存在 `next_offset` 时继续以 `--offset <next_offset>` 读取，直到它为 `null`。逐页保留已经收敛的主线与日期，不因前一页已形成初步结论而省略后续页。已确认周期报保持不变；只有本人明确要求重做时才使用 `begin --redo`。没有 confirmed 日报时停止，不用空白、draft 日报或重新采集的证据代替。

完成标准：规范周期和 CLI 窗口一致；所有分页都已读取且来源只包含 confirmed 日报；缺失与 draft 日期已掌握但没有被误写成“这些天没有工作”。

## 二、建立跨日主线

按日期顺序读取全部来源日报。周期报的增量是任何单份日报里读不出的弧线：同一目标在周期内从哪里出发，经过哪些真正改变判断、方案或完成层级的转折，最后停在哪里。

先把日报里的工作按共同目标归并，再为每条主线收敛：

1. 周期起点与当时不成立的状态；
2. 真正改变方向或终态的关键转折及原因；
3. 最新结论与证明力最强的结果；
4. 周期终态和这段变化换来的能力、判断或避免的代价。

日报中的日常动作、重复验证、已被后续结论替代的中间状态和机械证据说明只用于理解，不逐日复述。不同项目只有真实服务于同一目标时才合并；名称接近不构成共同主线。完成层级按日报已写明的本地、测试、发布、生产或外部结果分别保留，不从前一层推导后一层。

完成标准：来源日报中的高重要性主线都有去向；正文不是按日期拼接；只看每条主线的标题和首段即可理解这段时间发生了什么变化、最终到了哪里。

## 三、写自适应草稿

导语用整个周期最重要的主题或判断收束，不逐项预告正文。周报可以按“本周推进”“完成与上线”“经验与复盘”“踩坑与反思”组织，但只保留真实成立的章节；月报、季报、半年报和年报按周期内形成的真实主题自适应组织，可以使用更连贯的复盘叙事，不机械放大周报模板。

“经验”只写能够迁移到下一次工作的认识。“踩坑”只写合理路径因隐藏约束失败、证据误导判断或系统出现非预期行为，并且已经定位出可复用避免方式的经历；普通修错、参数调整和未完成事项不算。周期报不设置“下周关注”“下月计划”等下一周期清单，后续动作由项目与 LifeOS Work 继续维护。

缺失日、draft 日、来源数量和其他生成时信息只由 CLI 当次输出与交付说明承担，不写入 frontmatter，也不为了完整性写进正文。只有来源缺口实质改变某条主线的可信范围时，才在该主线附近用自然语言说明当前能成立的结论。

正文延续日报的个人复盘视角：从动作、判断和结果起笔，省略机械的“我”；不写 Agent 取证过程、授权表述或防御性免责句。

完成标准：正文形成跨周期的新总结；没有日报拼贴、固定栏目凑数、下一周期清单或机械审计段落；经验与踩坑符合各自门槛。

## 四、写入与确认

```bash
lifeos reports periodic begin --period <PERIOD> --json
lifeos reports periodic write --period <PERIOD> --body-file <PATH|-> --json
```

`begin` 会确认当时至少存在一份 confirmed 日报，建立只含周期、窗口和状态的紧凑草稿，并在命令输出中返回当次来源覆盖；正文通过 `write` 写入既有 draft，不直接编辑 Runtime 文件，也不在正文中提供 frontmatter。若 `begin` 返回的来源清单与写作时读取的 `sources` 不一致，重新读取来源后再写，不使用旧正文覆盖新来源。

向本人交付草稿时，说明周期、confirmed 日报覆盖数、缺失日和 draft 日；这些属于确认依据，不自动进入报告正文。本人明确确认后才运行：

```bash
lifeos reports periodic confirm --period <PERIOD> --json
lifeos reports validate
```

确认只表示本人接受当前周期报草稿，不重新读取或比对日报。完成标准：周期报保持 draft，直到本人明确确认后才成为 confirmed，随后 Reports 全量校验通过。

## 边界

Periodic 不创建或修改日报，不生成 Work，也不修改项目状态或 Obsidian。周期报暂不进入 LifeOS Web。
