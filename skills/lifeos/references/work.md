# Work 工作流

通过 `lifeos work` 读写 LifeOS 私有工作账本。项目正文和正式状态仍归对应 Project Workspace；项目名称、别名、scope、当前目录和核心 DChat/Cooper 入口来自动态 Project Catalog 中的 `lifeos-project.json`。Work 只保存个人工作脉络、行动闭环、稳定 `project_key` 和个人项目跟踪状态，不复制项目静态内容或绝对路径。

## 授权门槛与分支

“事情要做”是日报或对话中的后续判断，不自动进入 Work。只有本人明确要求或确认写入 LifeOS Work 才进入创建分支；对象类型按 `work-model.md` 选择，只有真实歧义会改变结果时才询问。

- **读取：** 只执行读取命令，回答请求的范围、过滤条件、时间窗和空结果。
- **创建：** 先读必要事实，按 `work-model.md` 选对象并生成稳定幂等键，再 create-only 一次。
- **变更：** 只有明确的已有 ID 和当前意图才更新、关闭、取消、归档或改期；状态原因和完成证据按 `work-model.md` 处理。

日报候选、会话结论和“应该记下”的建议都先留在当前回答或日报里。本人另行确认“记个待办”“建个事项”“收进闪念”或等价表达后，才进入 create-only，并逐条回收返回 ID。一次确认不扩成多个对象；未提供的负责人、日期、价值和期限保持未知。

责任方为本人时使用 `--responsible-kind self`，不传 `--responsible-party`；CLI 从
`ENT-SELF` 写入规范名称。个人或组织只写已确认的真实名称。人类可读输出中省略
self，只显示具名 person / organization；字段缺失或 unknown 不显示、不猜测。

## 读取分支

当前工作/待办查询采用 `lifeos work brief --mode current` 的用户易读结构。
14:00 前瞻提醒直接使用 `lifeos work brief --mode current`；18:00 晚间收口使用
`lifeos work brief --mode closeout`。两者都是确定性只读视图，Agent 直接转发 CLI
原生 Markdown，不再自行读取 JSON、重算日期、去重或重排。
`current` 只展示有可见未完成待办的推进中事项；没有可见待办的事项不展示。同一事项下的可见待办先按 `due_at` 由早到晚排列，逾期越久越靠前；无截止日待办再按最新 `task_started.started_at` 由早到晚排列，没有开始事件的放在最后。`active / waiting` 只决定可见范围，不覆盖时间顺序。`due_at` 过去才是结果逾期。开始推进日期只从 `task_started` 事件派生，里程碑阶段目标使用 `target_at`。`next_action` 中的 `260825开始……` 只按原生文本转发，不解析为日期，也不据此筛选、排序或提醒。
`current` 的闪念按创建时间倒序排列，只展示名称；状态与上下文不进入当前简报，需要时再查询闪念专属视图。
筛选只改变记录范围，不改变分组、状态、日期和条目层次。
只有本人明确要求改变展示方式时，才转换格式。

1. 只读取请求需要的对象、时间窗、项目或状态；没有过滤时标明全量。
2. 分开报告来源事实、已确认变化和推导；说明空结果、无匹配和未覆盖范围。
3. 请求字段已完整回答后停止，不顺带创建或修订记录。

完成标准：请求范围和字段已回答，本分支没有 create、update、close 等写入动作。

## 写入分支

1. 回读目标记录及必要事实源，确认对象、当前状态和本人的明确授权。
2. 读取 `work-model.md` 中与该对象或状态相关的规则；新增或更新事项时，先按其中的 `next_gate` writing rule 收敛为一句可观察门槛，不把日期、背景或任务清单塞进该字段；缺少会改变结果的字段时询问，不补造。
3. 按稳定来源、对象类型和不可变来源身份生成或复用幂等键；相同请求重试复用同一键。
4. 执行一次对应 create 或明确授权的变更，回读对象和事件 ID。
5. 一批写入后运行一次 `lifeos work validate`，报告新增、变化、幂等处理、验证结果和待本人判断项。

完成标准：每个写入都有明确授权、稳定来源和稳定幂等键；验证通过；返回 ID 与实际变化可回读；候选和推导没有被写成账本事实。变更分支还要说明变更前后状态、本人给出的原因和对应历史事件。

## 交接与失败

Daily 交接候选时保留本人原话、事实来源、已确认字段和不可变来源身份。Work 返回对象或事件 ID 后，Daily 只保存该 ID 与结果摘要，不复制 Runtime 内容。

入口、Schema、Project Catalog、权限或验证失败时报告具体阶段和原始错误，保持账本不变；先按原幂等键回读，不通过换参数或换键把失败改写成已完成。发现单个跟踪项目暂时不可用时保留 `project_key` 和 Work 事实，只报告 linkage warning，不猜测路径或自动取消跟踪。旧项目路径注册只有在本人授权、完整 Catalog 对账和备份均通过时才使用公共迁移命令；不直接编辑 Runtime。
